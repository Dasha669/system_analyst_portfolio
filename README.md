# Оптимизация процесса смены паспортных данных клиента (1С ↔ aCRM)

**Автор**: Дарья  
**Дата:** 15.08.2026  
**Роль:** Стажёр системный аналитик

---

## 1. Описание проблемы (AS IS)

В салоне связи для смены паспортных данных клиента сотрудник использует две системы:

1. **1С** — основная система для работы с договорами и биллингом.
2. **aCRM** — дополнительная система для управления клиентскими данными (интерфейс на английском языке).

**Текущий процесс:**
1. Сотрудник получает от клиента новый паспорт.
2. Проверяет данные в 1С.
3. Переходит в aCRM (отдельный вход, английский интерфейс).
4. Вручную вносит новые паспортные данные.
5. Возвращается в 1С и подтверждает операцию.

**Боли процесса:**
- Двойной ввод данных в две системы.
- Интерфейс aCRM перегружен и не интуитивен.
- Сотрудники боятся ошибиться из-за незнания терминов на английском.
- Время операции: ~15 минуты на одного клиента.

---

## 2. Предлагаемое решение (TO BE)

Внедрить в интерфейс 1С единую форму для смены паспортных данных, которая автоматически синхронизируется с aCRM через API.

**Новый процесс:**
1. Сотрудник вводит новые данные один раз в 1С.
2. Система автоматически отправляет запрос на обновление в aCRM.
3. Сотрудник подтверждает операцию в 1С.
4. Получает уведомление об успешном обновлении.

**Ожидаемый эффект:**
- Сокращение времени операции до 5 минуты.
- Исключение ошибок ввода (один источник данных).
- Упрощение интерфейса для сотрудников (всё в одной системе).

## 4. Модель передаваемых данных

При обновлении паспортных данных между 1С и aCRM передаются следующие поля:

| Поле | Тип данных | Описание |
|------|------------|----------|
| client_id | integer | Уникальный идентификатор клиента в 1С |
| passport_series | string | Серия паспорта (4 цифры) |
| passport_number | string | Номер паспорта (6 цифр) |
| issue_date | date | Дата выдачи паспорта |
| issued_by | string | Кем выдан паспорт |
| department_code | string | Код подразделения (формат 000-000) |

---

## 5. Бизнес-правила

- Если новый паспорт не совпадает со старым — отправить запрос на обновление.
- Если клиент не найден в 1С — отобразить ошибку и прервать операцию.
- Если aCRM недоступна — отложить запрос и уведомить сотрудника.
- Все изменения должны быть подтверждены сотрудником перед отправкой.
